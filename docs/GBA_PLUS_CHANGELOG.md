## 已知里程碑（历史快照，实机证据以实际反馈为准）

### 2026-10-16 — 合并测试：ROM图鉴编号 + 新精灵IV/EV — `b66810d7`

- 用户明确要求将待办②图鉴编号与③领取时自定义IV/EV合并到同一APK，以减少反复下载安装。
- 对用户实际上传、SHA-256已匹配的32MiB GBA ROM离线解析：`0x31DC82` 为411个物种→图鉴序号 `UInt16 LE` 映射，411项唯一，抽样：物种6→编号6、物种277→编号252、物种404→编号382。应用在校验完整ROM哈希后读取此映射；**地图是 ROM 记录，不代表已手机核对图鉴实际显示页面（地区/全国模式可能有差异）**。
- 精灵搜索由内部物种编号切换为ROM图鉴序号。避免在普通UI展示内部物种ID。为保护存档，物种252～276暂不允许赠送（需要单独验证），未知/无映射编号拒绝操作。
- 新增领取时6项IV（各0～31，默认全31）与EV（各0～255、总和≤510，默认0），顺序 HP/攻击/防御/速度/特攻/特防；加密原位写入 Gen III Effort 子结构以及 Misc IV位域。旧盒中精灵、队伍均不修改；修改前仍然备份。
- 新增 `EmeraldQuickSavePatcherTest.kt` 加解密反算、盒中写入、校验和/未修改原件，以及非法IV/EV拒绝测试。
- **测试状态：代码已提交，最新一次APK/单元测试结果须按对应SHA查看Actions。尚未用户手机实测。**
- **合并测试步骤**：用图鉴编号6（喷火龙）、252（木守宫）、382（盖欧卡）逐个核对ROM映射与游戏图鉴显示；分别选择Lv.50、指定性格/闪光、IV `0,1,16,29,30,31`、EV `252,0,4,250,0,4`（合计510），领取进电脑，取出查看属性，保存退出重进；未确认这些结果前不能转✅。
- **稳定性回归**：检查原有无限金钱/大师球、穿墙关停、原六队员IV/EV编辑，核对精灵PC已占位置不被覆盖。
- 后续：解析未支持的252～276物种、核实游戏内图鉴的显示模式，后续才拓展特性/技能/经验共享。


### 2026-10-16 — 指定精灵等级 1～100（实现待验证） — `8b3eca48`

- 用户上传的 `口袋妖怪 漆黑的魅影 5.0EX+BW.gba` **在本地 SHA-256 核验完全匹配**白名单 `389363bb2c87b8f197f23d67c11e459cc9f46befec75dc57a9e6fdac898eccc2`；ROM 文件**仅用于本地分析，未上传仓库**。
- ROM header `0x1BC` 的指针定位基础属性表偏移 `0x3203CC`；每个物种28字节，字节19为成长类型。抽样：物种内部ID 6为成长类型3、25为0、150为5；**这些是 ROM 内部物种ID，不是图鉴编号**。
- 新增六种 Gen III 经验成长曲线（1～100级），领取时根据 ROM 物种成长类型计算经验，并写入加密盒中精灵结构；选择等级有效性检查（1～100）。
- 新增单测覆盖六条成长曲线、边界/错误输入、加密盒记录经验写入及旧存档不变。
- **当前状态：已实现代码，尚未确认最终 APK 编译和用户手机取出精灵后等级显示、存档重载一致性**。不得标记为实机验收。
- 潜在问题：若该改版对标准成长曲线有特殊改动，仍需在游戏内对照样本；只读取 ROM 数据确认成长类型，不代表经验曲线被逐条验证。
- 下一步：检查对应 SHA 的 CI 工作流结果；稳定后进行 Lv.1/Lv.50/Lv.100 各选一只精灵的领取、取出、保存/重开验证；然后调查游戏内图鉴编号映射。

## 填写原则

1. 每条记录对应一个明确的**提交 SHA**，而不是模糊的“最新版本”。
2. 发现重复错误，应新建/追加到 [问题复盘](GBA_PLUS_KNOWN_ISSUES.md)，写出防再犯措施和能重复执行的检查。
3. GitHub Actions 排队/运行中只能记为「未出结果」；不要预先写「通过」。
4. 用户设备测试结果可填到记录，但必须写明测试的是哪个 APK；与 GitHub 源码不同不能混用。
