### 发布检查（逐项打勾）

- [ ] 本次提交与 APK artifact 的 SHA 完全一致；没有下载旧分支的 APK。
- [ ] Kotlin/Gradle 编译、native 相关测试、存档回归、ktlint 的结论均已填。
- [ ] 验证修改指定精灵不会覆盖任何旧盒位/队伍；坏校验或未知 ROM 拒绝。
- [ ] 穿墙及其它金手指经历开启→关闭→继续玩→保存→退出→重进测试。
- [ ] 快捷功能开关检查关闭不再补充、已取得资产不消失；满口袋/盒安全处理。
- [ ] 回归用户最在乎的当前游戏 SAV 直接编辑、逐只 IV/EV、颜色/按钮。
- [ ] 备份存档，确认覆盖安装不会清除旧应用数据；绝不建议为解决签名冲突直接卸载。
- [ ] 文档中区分**代码实现、CI通过、手机实测**，尚未验证不写“已完成”。

- 用户确认无限金钱、大师球、指定精灵领取在手机上能工作；后续确认保存金手指的编辑与已有基础功能正常运行。
- 本项是用户功能反馈，不代表满盒、所有 ROM、属性自定义或异常路径均通过。

## 填写原则

1. 每条记录对应一个明确的**提交 SHA**，而不是模糊的“最新版本”。
2. 发现重复错误，应新建/追加到 [问题复盘](GBA_PLUS_KNOWN_ISSUES.md)，写出防再犯措施和能重复执行的检查。
3. GitHub Actions 排队/运行中只能记为「未出结果」；不要预先写「通过」。
4. 用户设备测试结果可填到记录，但必须写明测试的是哪个 APK；与 GitHub 源码不同不能混用。
