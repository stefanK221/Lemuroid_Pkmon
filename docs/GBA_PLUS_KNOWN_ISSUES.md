# GBA Plus 常见故障、防再犯清单（持续积累）

> 这不是“错误都已经修好”的声明。每个问题需填写**发生版本、证据、根因、修复、回归用例、剩余风险**；未知的根因写“待确认”。开发前先查这里，防止重复尝试已失败的方法。

| 编号 | 历史问题 / 触发条件 | 已知原因或线索 | 禁止的重复做法 | 必做的预防/回归 | 当前边界 |
|---|---|---|---|---|---|
| R01 | GBA 游戏画面颜色异常 | 先前替换模拟器/核心后出现；用户反馈 Lemuroid 原核心色彩正常 | 不经画面回归就替换核心/渲染管线 | 同 ROM 对比地图、对话、切换场景，确认颜色、UI 按钮可点 | **每次更改 native 或 GL 层重新实测** |
| R02 | 穿墙开启后关闭仍有作用 | mGBA 旧行为曾忽略 `retro_cheat_set(enabled=false)`，补丁可能残留 ROM/内存 | 只保存 `enabled=false` 就声称“已关闭” | 明确清理核心代码/恢复补丁；跑 native 回归；游戏里开启→关闭→撞墙；保存重开复测 | 即便清除代码，已修改的存档/即时状态可能有残留 |
| R03 | 穿墙重启后丢失/或重启残留 | 持久化状态与实时核心状态混淆 | 把“保存开关”当成“核心已执行”；自动启用危险旧代码 | 进入游戏时核对真实状态；退出时清理；显示生效/失效提示 | 状态语义需按实际功能定义 |
| R04 | 金手指按钮点不动 | 历史手机反馈出现过；确切根因未追踪 | 只检查 APK 编译成功就宣布按钮可用 | Android 实机点击 UI、弹框、滚动、返回、横竖屏、遮挡 | 仍需 UI 回归 |
| R05 | 金钱数值没变化 | 历史测试时曾出现；改版 ROM 内存布局与 UI 观察时机可能不同 | 复制普通绿宝石的偏移到任意改版 | 对 SHA-256 白名单，实际消费后回补/关闭后不回补，检查满数/加密键 | 用户目前报告目标 ROM 可用 |
| R06 | 大师球覆盖其他物品 / 满球袋 | 背包精灵球格受容量和加密结构约束 | 无条件向固定槽写入 | 先识别已有大师球或空槽，满包拒绝，检查解码/校验 | 继续补满包回归 |
| R07 | 指定精灵领取错物种 | **游戏内图鉴号≠全国图鉴号≠存档内部物种 ID** | 按编号直接写 species ID，或未经验证映射即发布 | 从已校验 ROM 提取映射；图鉴号→名称→内部 ID 三方抽样对比，未知号拒绝 | 游戏内图鉴映射尚未完成 |
| R08 | 修改队伍导致其他精灵变化或 SAV 损坏 | Gen III PID 排列/加密/校验和、双存档槽；错误偏移会伤及其他记录 | 覆盖原文件，逐只修改不做全队 diff | 原样备份；仅编辑选中成员；验 party/section checksum；未选中记录逐字节对比；重载 | ROM hack 仍可能不同 |
| R09 | 收到无效精灵、蛋、闪光/性格不对应 | PID/TID/SID、经验等级、招式、特性约束相互依赖 | 直接把“闪光”设成布尔值，或任意填造性格/技能 | 使用合法结构及 ROM 表；生成→入盒→取出→查看能力→战斗→保存/重开 | 等级/性格/闪光尚未实现 |
| R10 | 金手指搜索/收藏排序后开关错条目 | 展示列表 index 不等于核心存储列表 index | 把筛选后 `forEachIndexed` 下标传给核心 | 保留原始存储索引，启用 A 不能改变 B；筛选+排序+收藏单测/实机 | 新 UI 已实现，需实机回归 |
| R11 | 批量关闭只关闭一部分 / 存储和核心分叉 | 连续更新 SharedPreferences 可能中途失败 | 多次零散写状态后假定事务成功 | 清核心后一次性写 disableAll；故障注入、异常提示、重启核对 | 最终 native 状态仍需游戏内回归 |
| R12 | GitHub 旧分支/旧 APK 被误认为“最新” | `feature/gba-plus-foundation` 和 `feature/gba-plus-quick-tools` 并存，历史上曾查错 | 仅按工作流名字或“最新”的口头描述识别产物 | 先查全部分支 head，再比对 artifact 的 `head_sha` 与目标 commit；附 Actions URL | 已多次发生，应永久执行 |
| R13 | APK 编译失败反复返工 | 历史包含 CMake 重复符号/VFS 缺失、脚本 CRLF、SDK/NDK 定位问题 | 不核对固定 core revision、NDK 和 LF 就修改构建脚本 | 固定 mGBA `c758314a639aa0066e7b65a8341448181b73c804`、NDK `27.2.12479018`、JDK17；native 回归+APK 构建 | 变更工具链须专门验证 |
| R14 | Checkstyle 红灯被 APK 绿灯掩盖 | 构建和 lint 属于不同工作流；历史 ktlint 失败 | 只看 APK 成功就声称“全部测试通过” | 分列 Build/Unit/native/ktlint/实机；记录失败日志和待修复原因 | 未有证据时不能宣布已解决 |
| R15 | 安装 APK 后丢存档 | 不同签名/包名覆盖失败，卸载可能清除应用内部数据 | 为了更新而建议直接卸载/清数据 | 先导出/备份 SAV，确认包名签名，再覆盖安装；失败保留旧版 | 任何新 APK 都须提示 |

## 每次开始改动前的六个问题

1. GitHub **哪个分支**是真正更新目标？head SHA 是什么？
2. 此 ROM 的 **SHA-256** 是否属于已适配版本？字段和图鉴映射是否经过验证？
3. 是否会覆盖用户原本的 SAV、队伍、盒子、其它背包物品？
4. 当前需求可否用**存档安全编辑**实现，还是必须在 native 运行时插桩？开关如何真正撤销？
5. 有没有同类问题（R01–R15）及可重复的测试？是否新增了回归用例？
6. 最新 APK、相关单元测试、native 测试、lint、**手机实测**是否分别核对，并写入变更记录？

> 不提交用户的 ROM、私人 SAV 或密钥到仓库。问题复现优先用合成数据或用户本地授权的 ROM。
